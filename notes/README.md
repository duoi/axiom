## 2026-10-01

- New UI windows carry a transparent margin (`HUDSplitChromeLayout.windowMargin`: 8pt left, right, bottom) so the open spring, which swings edge pills about 5pt past the card, is not clipped. `HUDPanel` keeps all sizing in card space (`cardFrame`, `setCardFrame`) and adds the margin only to the window frame; `HUDChromeWrapper.splitFrames()` offsets the card inside it. Classic uses no margin.
- New UI pills no longer intercept clicks. `PillGlassView` used to claim the hit and forward mouse events to its hosting view, but SwiftUI ignores events whose hit view is not the host, so it passed every click back up the responder chain: pills did nothing, and a pill that kept forwarding overflowed the stack (the Agent crash). Clicks now go straight to the hosting view; the press shrink comes from `HUDPillPressMotion`. `newUIPillClickRunsItsAction` clicks the live Agent and Screen pills with synthetic events.
- New UI dismiss: pills jumped into the tuck on the first frame, then sprang back out while the card faded, because closing treated openness as progress toward the tuck. `pouredFrames` now always runs tuck to seat by openness, and dismiss uses an ease-in (`pourDismissDuration` 0.24s) with no spring, finishing before the fade does.
- New UI with the Agent pill measured 568pt of pills in a 560pt card, so Add context ran under the shortcut pill. That row now uses a paperclip circle (`HUDPillID.contextIcon`). Agent and an armed capture highlight the whole pill instead of an inset capsule inside the glass.
- Switching New UI in either direction left the glass empty: `mount()` pulled the prompt out of the glass, then reassigned the same `contentView`, which is a no-op. It now clears `contentView` first, swaps the hosting region in the remount, and refocuses the field when the card is up. `newUIKeepsThePromptTypableAndSurvivesTurningItOff` drives the live panel through both switches.
- Debug builds use the keychain again. Keys saved in Settings survive a rebuild because Debug is signed with a stable Apple Development identity. `.env` and the bundled `dev-endpoint.json` only fill a key the keychain does not have. Writes fall back to the login keychain when the data-protection keychain reports a missing entitlement.
- Screen capture no longer hides the card. The shot leaves out every window Axiom owns (`ScreenGrab.excludedWindowIDs`), so the card stays up on Enter.

- A long reply follows the newest line while tokens are still arriving. Scrolling up holds that place. Returning to the end follows again. Growing text is not treated as a scroll. Capture: `notes/captures/hud-reply-tail.png` (40-line reply, last line in view).

- The error lip uncovers as the window grows downward. The plate stays on the top edge for the whole 160ms ease, including while the gap is still shorter than 28pt, so the card no longer shifts up and then drops back. Dismiss slides the lip back under the same way. A still cannot show the ease. Settled capture: `notes/captures/hud-error-lip-emerge.png`.

- User-facing copy is set up for localization. English stays in the source. `AIHUD/Localizable.xcstrings` is the string catalog, and `AIHUD/InfoPlist.xcstrings` holds the privacy prompts. Model prompts stay in code. They are saved settings, and they contain the `%datetime%` token.

- Card shortcuts stay out of the way while the field has marked text, so Return can confirm an input method. Quitting or replacing the session during an open-link prompt declines that prompt instead of leaving the wait hanging. A failed Anthropic tool result sets `is_error`.

- The repo no longer contains a development signing identity, a home-directory path, or a cleartext exception for a private host. Debug signing is ad-hoc unless `Config/Signing.local.xcconfig` sets one. A Debug build allows `http` for loopback and for the gitignored dev endpoint host, and writes that host into the built app's App Transport Security exceptions only.

- The bundle id is `com.duoi.axiom`. Keychain items and history use that id. An existing install under the old id will not see its old keys or chats.
